# ADR-012: aick-upgrade 플러그인 모드 분기 — "upgrade EXEMPT" 입장 전환

- **상태**: 채택 (2026-06-13, v4.8.0)
- **관련**: ADR-011(CC 기능 채택), v4.3.0 플러그인 자기완결형 경로

## 맥락

v4.3.0의 플러그인 이중모드 전환에서 `aick-upgrade`는 **EXEMPT**로 분류했다 — 클론 소스를 받아 로컬 프레임워크 디렉토리를 교체하는 스킬이라 플러그인 모드와 무관하다는 판단이었고, 당시에는 옳았다(그 시점까지의 마이그레이션은 전부 파일 교체로 전파 가능했다).

v4.8.0에서 전제가 깨졌다: **A2 gitignore 엔트리**(`add_gitignore_entry` 마이그레이션)는 사용자 리포 안의 `.gitignore`를 수정해야 하는데, `/plugin update`는 플러그인 캐시만 교체하고 사용자 리포 파일은 건드릴 수 없다. 플러그인 모드 기존 프로젝트에는 이 마이그레이션이 도달할 공식 경로가 없었고, `aick-health-check` SI-06은 이 상태를 "EXEMPT"로 박제하고 있었다. 부수 위험: 가드 부재로 플러그인 사용자가 `/aick-upgrade`를 실행하면 클론 플로우가 로컬 프레임워크 디렉토리를 생성(의도치 않은 시드 전환)했다.

## 결정

1. **aick-upgrade에 설치 모드 판별(Step 0.5)과 플러그인 모드 플로우(P1~P6)를 신설**한다. 플러그인 모드 = 프로젝트-로컬 마이그레이션만(gitignore 엔트리·project.json kitVersion·CLAUDE.md 재생성, README는 마커 존재 시만) — 파일 교체 없음, 로컬 프레임워크 디렉토리 생성 금지.
2. 모드 판별은 **텍스트 치환 기반**: `${CLAUDE_PLUGIN_ROOT}`는 env 변수가 아니라 로드 시점 치환(CLAUDE.md 판정 규칙과 동일) — 앵커 경로의 치환 여부(D1) + 빌트인 시드 glob(D2). 하이브리드(둘 다)는 클론 플로우(로컬 시드 SSOT).
3. **SI-06 autoFix(버전 직접 스탬핑)는 제거**한다 — 마이그레이션 미적용 상태로 버전만 정렬하면 P2 "이미 최신" 분기로 빠져 미적용 마이그레이션이 영구 마스킹된다. 드리프트 INFO는 `/aick-upgrade` 실행 안내로 대체.
4. 업데이트 절차 공식화: 플러그인 모드 = `/plugin marketplace update`(파일) → `/aick-upgrade` 1회(프로젝트-로컬).

## 비범위 (명시적 보류)

- **클론 모드 축소/제거** (파일 교체 절반을 떼어내는 재편): 클론/시드는 공식 지원 경로(eject-guide·제거 안전성 FAQ)이고, 강제 전환은 별도 major 결정. 재평가 트리거 = 플러그인-only 배포 정책 채택 시.
- **SessionStart 훅 자동 마이그레이션**: 훅은 R4 비차단·상태 쓰기 금지 원칙 — 자동 적용은 채택하지 않음. 재평가 트리거 = 마이그레이션 미적용으로 인한 실사고 보고.
- TEMPLATE-ENGINE `extract_custom_section` 마커 순서 가드(모드 공통 기존 경로 하드닝) — 후속 후보로만 기록.

## 근거 기록

- 플러그인 모드 적용 가능 마이그레이션 대상은 **P4 백업 4파일(CLAUDE.md·README.md·.gitignore·project.json)로 한정** — migrations.json에 새 change type을 추가할 때 P4 백업 목록 동시 확장 의무.
- migrations.json `from` 필드는 문서화 용도 — 적용 필터는 `current < to ≤ target`만 사용(본 작업에서 최초 명문화).
- kitVersion 기록은 P5의 **마지막** — 중간 실패 시 SI-06 드리프트 신호가 살아남아 재실행을 유도(범프 선기록은 데드 브랜치 클래스 — 릴리스 멱등 가드 A3 학습과 동족).
